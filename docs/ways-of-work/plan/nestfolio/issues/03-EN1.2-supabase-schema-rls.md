# Technical Enabler: Supabase schema + RLS

**ID:** EN1.2 · **Type:** Enabler · **Feature:** F1 · **Epic:** E1
**Labels:** `enabler` `priority-critical` `database`
**Estimate:** 8 pts (was 5 — added sync/persistence tables)
**Blocked by:** EN1.1

## Description
Create the core Postgres schema in Supabase and lock it down with Row-Level
Security so every row is scoped to its owning user. Includes the
**async-sync persistence layer** (see `sync-and-persistence-design.md`) so
transactions + historical prices are stored once and only appended to.

## Tables — core (user-scoped, RLS `user_id = auth.uid()`)
- `accounts` (id, user_id, name, type, currency)
- `portfolios` (id, user_id, name, parent_id ⟶ self, target_pct)
- `holdings` (id, user_id, portfolio_id, asset, amount, source, wallet_ref)
- `transactions` (id, user_id, date, type, source_account, dest_account, amount, category, note)
- `liabilities` (id, user_id, name, balance, type)
- `snapshots` (id, user_id, taken_at, net_worth, breakdown jsonb)

## Tables — sync & PnL persistence
- `wallets` (id, user_id, address, last_synced_block, last_synced_at, sync_status) — sync cursor
- `wallet_transfers` (id, user_id, wallet_id, tx_hash, log_index, block_number, ts, token_address, token_symbol, direction, counterparty, raw_amount, decimals) — **unique `(wallet_id, tx_hash, log_index)`** (idempotent appends)
- `trade_events` (id, user_id, wallet_id, ts, type, ticker, shares, usd_value, unit_price, price_source, tx_hash) — classified events
- `cost_basis` (id, user_id, wallet_id, ticker, shares, cost_basis, realized_pnl, updated_at) — **unique `(wallet_id, ticker)`**, materialized ledger
- `price_history` (ticker, date, close) — **global, market data, unique `(ticker, date)`, immutable**
- `live_prices` (ticker, price, fetched_at) — **global, TTL cache**

## Implementation Tasks
- [ ] Migrations for all tables + FKs (incl. `portfolios.parent_id`) + unique constraints above.
- [ ] RLS `user_id = auth.uid()` on user tables.
- [ ] `price_history` / `live_prices` = **global read-only** (only service role / sync job writes); no user_id.
- [ ] Seed enums (transaction type, holding source, trade_event type, sync_status).

## Acceptance Criteria
- [ ] All tables created with correct relations + unique/dedup constraints.
- [ ] RLS blocks cross-user reads/writes; market-data tables are read-only to clients.

## Definition of Done
- [ ] Migrations run clean; RLS + dedup verified by T1.1.
