# Technical Enabler: Cost-basis ledger (average cost)

**ID:** EN6.2 · **Type:** Enabler · **Feature:** F6 · **Epic:** E1
**Labels:** `enabler` `priority-high` `backend`
**Estimate:** 5 pts
**Blocked by:** EN6.1 (events), EN4.3 (historical price)

## Description
Maintain a per-ticker **average-cost** ledger by walking classified events in
chronological order. Acquisitions add cost; disposals realize PnL against the
running average. **Option A:** 1-leg deliveries/sends are priced at the historical
equity price at their timestamp; 2-leg trades use the exact on-chain USD.

```
ACQUIRE (BUY or DELIVERY):
   shares += q ; cost += (BUY: usd_paid) OR (DELIVERY: q × histPrice(ticker, date))
DISPOSE (SELL or SEND):
   avg = cost/shares
   proceeds = (SELL: usd_received) OR (SEND: q × histPrice(ticker, date))
   realized += proceeds − avg×q ; cost −= avg×q ; shares −= q
```

## Implementation Tasks
- [ ] Chronological event loop per ticker; average-cost bookkeeping.
- [ ] Historical price lookup for 1-leg events via `price_history` (cached, immutable) — fetch only gaps.
- [ ] **Materialize** into `cost_basis` (`shares`, `cost_basis`, `realized_pnl`); update **incrementally** only for tickers with new `trade_events`.
- [ ] No new events → no recompute (realized PnL is stable between trades).
- [ ] (Optional later) Binance order-history import to override delivery costs (penny-exact).

> Runs inside the heavy sync (EN4.5). `cost_basis` table defined in EN1.2.

## Acceptance Criteria
- [ ] Remaining `shares` per ticker matches the live on-chain balance.
- [ ] Cost basis populated for all positions (no $0-cost holdings from unpriced deliveries).

## Definition of Done
- [ ] Ledger unit-tested incl. avg-cost across multiple buys + a partial sell.
