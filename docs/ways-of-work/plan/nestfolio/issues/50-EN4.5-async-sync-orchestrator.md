# Technical Enabler: Async sync orchestrator

**ID:** EN4.5 · **Type:** Enabler · **Feature:** F4 · **Epic:** E1
**Labels:** `enabler` `priority-high` `backend` `integration`
**Estimate:** 5 pts
**Blocked by:** EN4.2 (incremental sync), EN4.3 (price caches), EN6.2 (cost basis)

## Description
Orchestrate the **two-speed async model** so the app never re-fetches stored data.
See `docs/ways-of-work/plan/nestfolio/sync-and-persistence-design.md`.

```
on app open → /api/sync (async, non-blocking)
  HEAVY (incremental):  new transfers → classify → fill missing price_history
                        → rebuild cost_basis (realized) → reconcile → bump cursor
  LIGHT (TTL ~1–5 min): refresh live_prices if stale → recompute unrealized/total
read path: dashboard reads cost_basis + live_prices from DB instantly; UI revalidates
```

## Implementation Tasks
- [ ] `/api/sync` endpoint: runs heavy sync (delta only) + light refresh; idempotent.
- [ ] Debounce on-open sync; optional cron for background freshness.
- [ ] Live-price TTL cache; skip refresh when fresh.
- [ ] Read endpoints serve last-known from DB (never block on network).
- [ ] Revalidation signal to client (React Query/SWR or Supabase realtime).
- [ ] Surface `sync_status` (ok / degraded / running) + `last_synced_at`.

## Acceptance Criteria
- [ ] First sync backfills; subsequent syncs fetch only new blocks + stale live prices.
- [ ] Dashboard renders last-known data with zero network wait; updates after sync.
- [ ] Unrealized PnL updates on live refresh without any blockchain/history calls.
- [ ] Sync failure → last-known shown + status flagged, never blank.

## Definition of Done
- [ ] Orchestrator integration-tested: cold start, warm delta, stale-price-only, failure path.
